Five brands. One photo.

Factory Twins circles the listings on your Amazon or Walmart search that use the same product photo, then folds them into one price ladder so you can see what the name on the box costs.

Same photo ×5.

Search for "laptop stand" and page 1 can show the same factory photo again and again under names you've never heard of. Factory Twins hashes every thumbnail on the page and rings the ones that match in a shared colour. Press F and each group folds into one card: every price, rating and review count lined up under the same photo.

It compares photos, not products. A group can hold the original and a copy that borrowed its picture, so the reviews sit right under each price.

See what the name costs.

The fold card puts the cheapest and the priciest listing with the same photo side by side and shows the gap as a brand tax. Multi-packs are compared per unit, so a 3-pack never looks like a markup.

The listing with the most reviews is marked "Most established". A listing with almost no reviews that borrows a well-reviewed photo gets a note saying so. Demo listings, made up for this page.

Don't take our word for it.

Open the Proof lens on any group. Slide one photo over the other, or switch to Difference: where the pixels match, the frame turns black. The number underneath is measured, not guessed.

Demo photos are generated for this page. The five twins are re-saved, resized and slightly cropped copies of one image, so they are close to identical, not byte for byte equal, and the number says exactly how close. On a real store page, the lens uses the store's own thumbnails.

Useful even when you don't click.

After every search a small pill says what the page really holds: listings, distinct products, twin groups, and the biggest brand tax on the page. When nothing repeats, it says that too. Go to page 2 and it remembers page 1, so a photo that shows up on several pages is counted once.

How it works

  1. The decision

    Compare the photos the page already shows, on your machine, and claim only what the pixels prove.

  2. The naive version

    Drawing store thumbnails onto a canvas from the page fails: the browser blocks reading pixels from another site's images.

  3. The trick

    The extension re-reads each thumbnail from the store's own image server, inside an extension page that has permission for that one host, then hashes it locally: a 64-bit difference hash, a 64-bit DCT hash and a small colour signature. Two photos are twins only when all three agree and the titles name the same kind of thing.

  4. How it degrades

    If a store changes its page layout, the pill says it couldn't read the listings and offers a one-click layout report; nothing else breaks. Reduced motion turns the fold into a crossfade.

  5. Stack and licence

    WXT, TypeScript and React; MIT licence; no backend, no analytics, no account. Grouping 200 listings took about 8 ms in the stage-2 benchmark on the development laptop.

Nothing leaves your device.

There is no Factory Twins server to send anything to. The extension re-reads thumbnails from the store you are already on, compares them locally, and forgets the pixels right after hashing. The popup counts every image read by host, so you can check that each one went to that store.

Try it on your next search.

Factory Twins is not in the Chrome or Firefox stores yet, so for now you load it from source. It takes about two minutes.

Chrome and Chromium

pnpm install && pnpm build

Then open chrome://extensions, switch on Developer mode, choose Load unpacked and pick .output/chrome-mv3.

Firefox 128 and up

pnpm install && pnpm build:firefox

Then open about:debugging, choose This Firefox, then Load Temporary Add-on and pick the manifest inside .output/firefox-mv3.

Works on desktop Chrome and Chromium browsers, and desktop Firefox 128 and up, on Amazon.com and Walmart.com search pages. It cannot run on phones or in the store apps. On a phone, use the web app.

Open source, MIT.

The engine is pure functions, each store is one adapter file, and a test fails if the engine ever touches a browser-extension API. You can read all of it in an afternoon. Three things would help most:

  • Run the spike on live pages. Hashing is proven against fixtures and a local server, not yet against real amazon.com or walmart.com, or in real Firefox.
  • Check the selectors. The store adapters were written from the public page structure and tested on made-up fixtures. A capture of a real results page would show whether they hold.
  • Add a store. A new store is one adapter module with its own fixtures; nothing else changes.
